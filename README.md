# Бурятский язык — MVP

Приложение для изучения литературного бурятского языка с нуля по механике Duolingo: короткие уроки, серия дней, интервальные повторения. Аудитория — русскоязычные взрослые, интерфейс на русском.

Работает в **Expo Go** (без dev client и EAS). Всё хранится на устройстве; сервер (Supabase) необязателен — он добавляет вход, синхронизацию, друзей и ИИ-собеседника, только если в сборке заданы его ключи (см. «Сервер»). Аналитики и трекеров нет.

> **Контент.** Бурятский берётся из учебника, разговорника Burlang и машинного перевода с проверкой обратным переводом (`content/SOURCES.md`). У каждой единицы указан настоящий источник и стоит `verified: false`: сверка с носителем пройдёт в конце проекта. В dev-сборке на непроверенных единицах видна пометка, в релизе — по настройке в профиле.

## Запуск на iPhone через Expo Go

1. Установите Node.js 20+ и [Expo Go](https://apps.apple.com/app/expo-go/id982107779) на iPhone. Нужен Expo Go с поддержкой **SDK 58**.
2. В папке проекта:
   ```bash
   npm install
   ```
   ```bash
   npx expo start
   ```
3. Отсканируйте QR-код камерой iPhone. Телефон и компьютер должны быть в одной Wi-Fi-сети. Если сеть не позволяет:
   ```bash
   npx expo start --tunnel
   ```

Чек-лист ручной проверки на устройстве:
- онбординг → выбор цели;
- «Путь» → урок юнита «Звуки һ, ү, өө, н»: карточка «Что нужно знать», знакомство, выбор, сопоставление, сборка слова из букв;
- «Практикум» → «Слова»: ввод с панелью Ү ү Ө ө Һ һ над клавиатурой;
- «Практикум» → «Произношение»: запрос микрофона, запись, «Моя запись» звучит из динамика, а не из слухового;
- итог урока: точность, XP, ошибки;
- «Практикум» → «Ошибки» и «Диалоги»;
- «Практикум» → «Аудиоуроки»: плеер, перемотка по ленте, скорость 0,75×, отметка «прослушан» в конце;
- «Словарь»: поиск «хургуули» находит «һургуули»;
- «Профиль»: имя, смена аватара, достижения, тёмная тема, сердечки, сброс прогресса;
- хаптика на ответах.

## Курс (MVP)

| Юнит | Источник |
|---|---|
| 1. Алфавит и особые буквы Ү Ө Һ | учебник, стр. 1–2 |
| 2. Звуки һ, ү, өө, н | урок 1 учебника |
| 3. Йотированные гласные | урок 2 + §5, §8б введения |
| 4. Краткие/долгие гласные, минимальные пары | урок 3 + §7–8 введения |
| 5. Дифтонги | урок 4 + §9 введения |
| Тематические (Знакомство, Семья, Числа, …) | закрыты, ждут слов от носителя |

Занятие рассчитано на 2–4 минуты: 3–6 новых единиц и не больше 12 заданий (`MAX_TASKS` в `src/engine/lesson.ts`). Каждая новая единица сразу закрепляется вопросом, затем чередуются сопоставление, пары, ввод и контроль. Незавершённое занятие сохраняется и его можно продолжить. Урок с точностью ниже 70% считается завершённым, но не освоенным.

### Разговорный маршрут

Первая глава курса: 10 мини-уроков от «Поздоровайся» до «Поговори», каждый заканчивается сценой с Сэсэг. Реплики лежат в `content/templates/dialogue-route.csv`: у каждой есть роль (`partner`, `learner`, `extra`), источник и обратный перевод. После правки файла:

```bash
npm run import:dialogues
```

Реплики попадают в `words.json` и правятся также через общий CSV сверки.

### Сцены тематических глав

Название урока, навык и итоговая сцена лежат в `content/templates/thematic-scenes.csv` и загружаются той же командой `npm run import:dialogues`. Строки сопоставляются с уроками главы по порядку (`lesson` — номер урока в главе), поэтому после изменения состава слов проверьте, что название ещё подходит урокам.

## Практикум

Вкладка с тренировками по направлениям (`src/app/(tabs)/practice.tsx`, сессии — `src/engine/practice.ts`, экран — `src/app/practice/[section].tsx`):

| Раздел | Что внутри |
|---|---|
| Слова | интервальное повторение (SM-2) |
| Аудирование | «Что вы слышите?» по словам с записью; сначала уже знакомые |
| Произношение | «Послушай и повтори»: образец, запись своего голоса (`useAudioRecorder`), сравнение на слух, самооценка |
| Грамматика | карточка правила, минимальные пары, ряды гласных |
| Ошибки | слова с ошибками в истории (`lapses > 0` или низкий `ease`), самые трудные первыми |
| Диалоги | сцены из уроков с Сэсэг и Баиром |

Тренировка не засчитывает урок: ответы идут в повторение, XP — как за повторение. Автоматической оценки произношения нет — для бурятского её не сделать честно. Микрофон в вебе работает только по https; без разрешения задание показывает подсказку и всё равно засчитывается по самооценке.

## Бурятский мир

«Путь» по умолчанию — карта Бурятии (переключатель «Карта Бурятии / Список глав»). Места — Улан-Удэ, Иволгинский дацан, Байкал, Баргузинская и Тункинская долины, степь — объединяют главы курса; нерпёнок стоит у места со следующим уроком. На экране места — пара фактов о нём и его уроки. Места, их главы, факты и положение на карте — `content/world.json`; тест следит, чтобы каждая открытая глава была ровно в одном месте. Карта нарисована обычными View, без картинок и SVG.

## Разговоры с Сэсэг

Практикум → «Разговоры»: шесть сценариев (знакомство, рынок, кафе, семейные фото, поездка в Улан-Удэ, в гостях). Сэсэг говорит, ученик выбирает ответ; у каждого хода есть верный вариант, «почти» (засчитывается, нерпа объясняет, как лучше) и неверный (объяснение и ещё одна попытка). В конце — звёзды по ответам с первого раза; верные реплики, совпавшие со словами курса, идут в повторение и звучат записью.

Сценарии — `content/templates/conversations.csv` (`conv, title, scene, art, step, role, buryat, russian, verdict, explain`; `role`: `say` — реплика Сэсэг, `option` — вариант ответа, `reply` — ответ Сэсэг после верного). Загружаются вместе с маршрутом: `npm run import:dialogues`. Реплики, которых нет в курсе, команда перечисляет — они составлены вручную и ждут сверки.

## Задания, испытания, события

- **Задания дня** — три на день (набрать XP всегда первое), выбираются по дате и считаются из прогресса (`src/store/quests.ts`).
- **Недельное испытание** — 150 XP с понедельника по воскресенье.
- **Сезонные события** — `content/events.json`: Сагаалган (дата по лунному календарю записана таблицей — её нужно продлевать каждый год) и День Байкала (второе воскресенье сентября). Пока событие идёт, на «Пути» — баннер и праздничная тренировка; участие даёт достижение.
- **Коллекции** — в словаре: главы и «С записью», с числом выученных слов (слово выучено, когда его дважды вспомнили в повторении).
- **Напоминание** — профиль → «Напоминание»: локальное ежедневное уведомление (`expo-notifications`), только iOS и Android.
- **Перенос прогресса** — профиль → «Перенос прогресса»: выгрузка текстом и загрузка на другом устройстве, без аккаунта. Загрузка объединяет прогресс, а не заменяет.

## Сервер (необязательно)

Без настройки сервера всё перечисленное выше работает. Сервер добавляет вход по коду из письма, синхронизацию между устройствами, друзей с недельным рейтингом и свободный разговор с ИИ.

1. Создайте проект на [supabase.com](https://supabase.com) (бесплатного плана достаточно).
2. Примените схему: `supabase/migrations/20261112000000_init.sql` (SQL Editor или `supabase db push`). Таблицы `profiles`, `progress`, `friends`, `chat_usage` закрыты политиками RLS.
3. Скопируйте `.env.example` в `.env` и впишите URL и anon-ключ проекта. Для GitHub Pages те же переменные нужны при `npm run deploy`.
4. ИИ-собеседник: задайте ключ Claude API в секретах функции и разверните её:
   ```bash
   supabase secrets set ANTHROPIC_API_KEY=...
   ```
   ```bash
   supabase functions deploy chat
   ```
   Функция (`supabase/functions/chat`) отвечает от лица Сэсэг через `claude-opus-5-5`, не больше 40 сообщений в день на человека. Ключ хранится только на сервере.

**Конфиденциальность.** Без входа данные не покидают устройство. После входа на сервере хранятся: адрес почты (для входа), имя и аватар из профиля, прогресс (XP по дням, уроки, карточки повторения), список друзей, число сообщений ИИ за день. Друзья видят только имя, аватар и XP за неделю. Сообщения ИИ-собеседнику передаются в Claude API для ответа и в базе не сохраняются. Удаление аккаунта удаляет все эти записи (каскадно от `auth.users`).

**Контент без админки.** Слова, аудио и уроки по-прежнему правятся через CSV и команды импорта (см. «Как править контент», «Как добавить аудио»), а публикуются коммитом и `npm run deploy`. Отдельная веб-админка не нужна: проверка носителем идёт через `npm run review:priority` → `units.csv` → `npm run review:import`.

## Профиль и достижения

Имя и аватар хранятся в настройках, только на устройстве. Аватары заданы в `src/ui/Avatar.tsx`. Достижения вычисляются из прогресса (`src/store/achievements.ts`) и нигде не сохраняются. Когда занятие завершает главу, на экране итога появляется её значок.

Упражнения:
- выбор перевода;
- сопоставление пар;
- сборка слова из букв (с лишними буквами-двойниками ү/у, ө/о, һ/х) — в уроках;
- ввод с клавиатуры — только в повторении, когда слово уже дважды отвечено верно;
- минимальные пары;
- прослушивание — только если есть запись;
- ряды гласных;
- сборка предложения — только если у предложения есть перевод.

### Проверка ответов

Регистр, пробелы и знаки препинания не важны.

«Почти верно» засчитывается, если особые буквы заменены (ү→у, ө→о, һ→х) **и** получившееся слово не является другим словом курса. Например, «хун» вместо «хүн» — неверно. В минимальных парах допуска нет. Логика описана в `src/engine/check.ts`, тесты — в `src/engine/__tests__/check.test.ts`.

## Как править контент

Источники лежат в `content/sources/` и в git не попадают (см. `content/SOURCES.md`).

```
content/
  words.json  sentences.json  minimal-pairs.json   генерируются импортом, правятся через CSV
  alphabet.json  vowel-rows.json  notes.json         внесены вручную по страницам учебника
  course.json                                        раскладка по юнитам и урокам (генерируется)
  review/units.csv                                   выгрузка для сверки
  templates/thematic-words.csv                       шаблон для слов носителя
```

### Сверка с носителем

```bash
npm run review:export
```

Создаёт `content/review/units.csv`. Откройте его в Excel или Google Таблицах. Редактируемые колонки:
- `buryat`, `russian`;
- `alternatives` — через « | »;
- `form` — `lemma` или `form`;
- `translation` — для предложений;
- `excluded`, `verified` (да/нет), `comment`.

Колонки `book_text`, `review_reasons`, `typo_candidates` — справочные: в них текст книги и причина пометки.

```bash
npm run review:import
```

Это предпросмотр: показывает изменения и ошибки, ничего не записывает.

```bash
npm run review:import -- --apply
```

Записывает изменения и пересобирает курс. Подтверждённые слова попадают в уроки. Слова с подозрением на опечатку (`possible_typo`) и служебные пометки в уроки не попадают, пока их не проверят.

Повторный импорт учебника правки не теряет. Слияние идёт по исходной строке книги, id не меняются.

```bash
npm run import:textbook
```

### Слова носителя для тематических юнитов

Заполните `content/templates/thematic-words.csv`:
- колонки: `unit` (например «Семья»), `buryat`, `russian`, `alternatives`, `comment`, `speaker`.

```bash
npm run review:import -- --thematic --apply
```

Юнит откроется автоматически.

### Отчёт о состоянии

```bash
npm run validate:content
```

Показывает, сколько единиц не верифицировано, без аудио, с `needs_review`, без перевода. Падает, если контент не проходит схемы или в нём есть битые ссылки.

## Звуки интерфейса

Короткие звуки на верный, почти верный и неверный ответ, на собранную пару, на нажатие плитки, на конец урока и на награду. Файлы взяты из набора `soft` проекта [UI SFX](https://github.com/romainsimon/uisfx): аудио под CC0, лицензия лежит в `assets/sfx/LICENSE-AUDIO.txt`. Связка «событие → файл → громкость» задана в `src/audio/sfx.ts`. Чтобы сменить набор, скопируйте одноимённые файлы из другого набора uisfx (`sounds/<набор>/*.mp3`). Звуки выключаются в профиле.

## Как добавить аудио

TTS не используется, только записи носителя.

1. Список слов по приоритету (Ү, Ө, Һ → долгие гласные → минимальные пары):
   ```bash
   npm run audio:checklist
   ```
   Результат — `content/review/audio-checklist.csv`.
2. Сохраните запись как `assets/audio/{id}.m4a`. id и имя файла — в колонке `file`.
3. Пересоберите индекс: Metro требует статические `require`.
   ```bash
   npm run audio:index
   ```

После этого появятся кнопка прослушивания и упражнение «Что вы слышите?».

### Нарезка из аудиоуроков

Длинные аудиоуроки (`assets/audio/urok-*.mp3`, в git не попадают) построены парами «бурятское слово → русский перевод». Слова из них вырезаются по таблице `content/templates/audio-clips.csv`: колонки `id`, `file`, `start`, `end` (секунды), `status` (`skip` — не брать), `comment`.

```bash
npm run audio:cut
```

Команда вырезает клип с небольшим запасом по краям, срезает гул ниже 80 Гц, подавляет шум (`afftdn`), выравнивает громкость (`loudnorm`), добавляет мягкие края и пересобирает индекс. Нужен `ffmpeg` в PATH. После правки времени в CSV — `npm run audio:cut -- --force`.

Первая таблица собрана автоматически: распознавание речи нашло в уроках русские переводы слов курса и соседние бурятские слова. Каждый клип затем распознан заново; 20 клипов, где слышно другое слово, помечены `skip`. Записи носителя, но **лицензия уроков не подтверждена** (см. `content/SOURCES.md`).

В упражнении «Что вы слышите?» есть кнопка «Медленно»: та же запись в темпе 0,65.

### Аудиокурс и аудиоуроки целиком

Из 30 аудиоуроков (20 радиоуроков «Буряад FM» и 10 детских) взято всё, что удалось проверить:

- **Слова и фразы.** `content/templates/audio-candidates.tsv` — словарь кандидатов по темам радиоуроков в литературном написании. Распознавание находит в записях их русский перевод и соседнее бурятское слово; клип вырезается и распознаётся ещё раз. Прошедшие проверку попадают в `content/templates/audio-words.csv`, а оттуда в курс: `npm run import:audio-words`, затем `npm run audio:cut`. Новые слова — в главе «Аудиокурс «Буряад FM»», числа, цвета, одежда и части тела открывают свои тематические главы. Слово, которое уже есть в курсе, получает только запись.
- **Уроки целиком.** `assets/lessons/{fm-NN,kids-NN}.m4a` (моно AAC 32 кбит/с, шумоподавление, ровная громкость) и лента `content/audio-lessons.json`: русская речь текстом, бурятская — отметкой, слова курса — с переводом на своём месте. Экран — `src/app/listen/[id].tsx`, список — в Практикуме. Прослушанный до конца урок даёт XP один раз.

Конвейер (Python 3.11, `faster-whisper`, `wordfreq`, `ffmpeg`; запуск из корня, рабочие файлы — в `.audio-work/`):

```bash
python scripts/audio/transcribe.py assets/audio .audio-work/tr
```
```bash
python scripts/audio/find-words.py .audio-work/tr content/templates/audio-candidates.tsv .audio-work/found.json
```
```bash
python scripts/audio/cut-qa.py id1,id2
```
```bash
python scripts/audio/build-lessons.py
```

`cut-qa.py` принимает через запятую id кандидатов, которые надо пропустить, и пишет результат проверки в `.audio-work/qa.json`. Строки с низким сходством переносить в `audio-words.csv` не нужно.

## Разработка

```bash
npm run check
```

Запускает typecheck, eslint и jest.

- `src/app/` — экраны (expo-router);
- `src/engine/` — упражнения, проверка ответов, сессия;
- `src/srs/` — упрощённый SM-2;
- `src/store/` — zustand + AsyncStorage;
- `src/content/` — zod-схемы и загрузчик;
- `scripts/` — импорт, CSV, валидация, аудио.

## Обновление маршрута и практики

- Вместо схематичной карты — маршрут с иллюстрациями остановок, темами глав и кнопкой следующего урока. Пройденные и освоенные уроки считаются отдельно; освоение требует 70% точности.
- В словаре можно тренировать текущую подборку и результаты поиска, в том числе только освоенные слова. Раздел «Практика → Слова» запускает свободную тренировку до 10 заданий.
- В веб-версии перенос прогресса поддерживает скачивание и загрузку JSON-файла. Импорт проверяет даты, XP, результаты уроков и карточки до объединения; старые выгрузки поддерживаются.
